MSTPD topology examples

Each diagram below is a live spanning tree. A few lines of text in a <pre> block describe it, and the protocol behind it is MSTPD itself, compiled to WebAssembly. Press Start to run the clock, click a bridge or a link to see its state, double-click a link to cut it, and press Edit to change the topology and try something else.

A ring with an extra diagonal link

:protocol rstp

A @0,0  prio=4096
B @2,0
C @0,2
D @2,2

A -- B
A -- C
B -- D
C -- D
B -- C  cost=100

A has the best priority, so it becomes the root. A tree over four bridges uses only three cables out of five, so two cables have one end that discards frames. Which two depends on the cost of each hop: the diagonal B -- C gets a cost of 100, much lower than the cost the other links get automatically. Click a link to compare.

Following one BPDU

:protocol rstp

R @1,0  prio=0
A @0,2  prio=4096
B @2,2  prio=8192

R -- A
R -- B
A -- B

Play two steps, then look at the proposal R sends to A or at the two proposals R gets back. On the next step A sends two frames to R, and the second one is its agreement. You can also wait for the tree to settle and then cut R -- A: B offers A the path to the root that it still has.

Each of these links restarts the topology, replays it up to the moment it names and puts a red arrow on the frame it talks about.

Multiple links between two nodes

:protocol rstp

A @0,0  prio=4096
B @2,1  prio=8192

A -- B
A -- B
A -- B

Three cables between the same pair of bridges. A is the root and offers the path to it on all three. B picks one of them as its root port and keeps the other two as alternates. Double-click the cable that forwards: one of the spare cables takes over, and this needs a handshake, not a timer.

Classic STP is slow

:protocol stp
:forward-delay 4
:max-age 6
:max-hops 6
:tx-hold 3

R @1.5,0  prio=0
X @0,2
Y @3,2

R -- X
R -- Y
X -- Y

A triangle running the STP as a fallback protocol, with the shortest timers it accepts. There is nothing to negotiate here: a port on its way to forwarding waits in listening, then in learning, one forward delay in each state, whatever the bridge at the other end says. The convergence time in the bar is the time the handshake saves everywhere else on this page.

A shared cable brings back learning

:protocol rstp
:forward-delay 4
:max-age 6

R @0,0  prio=0
A @2,1

R -- A  R:no-p2p A:no-p2p

The no-p2p flag says the cable is not point to point, like a segment behind a hub: there may be more than one bridge at the far end. The proposal and agreement handshake is safe only with a single neighbour, so it is off here. Both bridges speak RSTP, but the transition is slow due to the learning state.

Root guard protects from a rogue

:protocol rstp

Core   @0,0  prio=4096
Access @2,0  prio=8192
Rogue  @2,2  prio=0     icon=🦹

Core -- Access
Access -- Rogue  Access:root-guard

Rogue claims a priority of 0 and would take the root away from Core. The Access port facing it has root guard, so it refuses the better BPDU: the port stops forwarding and stays that way for as long as Rogue keeps talking.

BPDU guard shuts down a rogue

:protocol rstp

Access @0,0  prio=4096
Rogue  @2,1  prio=8192  icon=🦹

Access -- Rogue  Access:bpdu-guard

BPDU guard is for the ports that should never see a BPDU at all. The first frame from Rogue takes the port down.

Talking to an old STP bridge

:protocol rstp
:forward-delay 4
:max-age 6

New  @0,0  prio=4096
Peer @2,0  prio=12288
Old  @0,2  prio=8192  proto=stp  icon=🐌

New -- Peer
New -- Old

Old only speaks STP. New recognises the older frames coming from it and answers with the same kind of frames, but on that port only. The details of that port show the STP fallback, while the port towards Peer keeps the rapid handshake. One old bridge slows down its own corner of the network, not the whole network.

A network too wide for one tree

# With max age set to 6, this chain of 12 bridges ends up with two
# bridges that both believe they are the root.

:protocol rstp
:max-age 6

b0 @0,0
b1 @1,0
b2 @2,0
b3 @3,0
b4 @4,0
b5 @5,0
b6 @5,2
b7 @4,2
b8 @3,2
b9 @2,2
b10 @1,2
b11 @0,2

b0 -- b1
b1 -- b2
b2 -- b3
b3 -- b4
b4 -- b5
b5 -- b6
b6 -- b7
b7 -- b8
b8 -- b9
b9 -- b10
b10 -- b11

A BPDU carries a message age that grows by one at every hop, and a bridge drops the BPDU once that age reaches max age. This chain allows only six hops from the root, so the far end never hears anything from b0 and picks a root of its own. Two roots, two trees.

A loop through a switch with no STP

:protocol rstp

A @0,0  prio=4096
B @2,0  prio=8192
C @1,2  proto=none  icon=🔌

A -- B
A -- C
B -- C

C runs no spanning tree and drops the BPDUs, so A and B learn nothing about each other through it. Both ports facing C end up forwarding and the loop A-B-C stays open.

Convergence with old information

:protocol rstp

R @1,0 prio=0
A @1,1 prio=4096
B @0,2 prio=8192
C @2,2

R -- A
A -- B
B -- C
C -- A

Let it settle, then cut R -- A. The three remaining bridges pass around what each of them still remembers of a root that has gone, and every one of them believes the others. It takes about ten seconds to settle.

A one-way link and dispute

:protocol rstp

A @0,0  prio=4096
B @2,1  prio=8192

B -> A

Demo of the dispute mechanism. Repair the link, wait for the tree to settle, then break one direction again. B hears nothing from A and treats its port as an edge port. Once A receives the worse BPDU from a designated port, the dispute mechanism starts. The state is not visible because A clears it as soon as it moves the port to discarding.

:demo
:protocol rstp

A @0,0  prio=4096
B @2,0
C @0,2
D @2,2

A -- B
A -- C
B -- D
C -- D
B -- C

Stan goes from cable to cable and cuts one every so often, Blobby repairs whatever is down. Press the stop button in the corner to stop the demo.
